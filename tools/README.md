# tools

- `gw.sh`: the only way to call Gradle (one build at a time).
- `consistency-check.mjs`: G-12 gate. Elements of one type must share size, position and alignment on every screen.

## How to run the consistency check

The app tags every element type (`ui/Tags.kt`, resource-ids `card`, `card-title`, `card-trailing`, `page-title`, `page-subtitle`, `section-label`, `chip`, `period-label-*`, `dock`, `island`, `gear`); the root sets `testTagsAsResourceId`.

1. Build and install the debug APK on the EMULATOR only (never the phone): `bash tools/gw.sh :app:assembleDebug`, then `adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk`.
2. Load the synthetic data (debug button "Carica i dati di esempio"), animator scales at 1.
3. For each screen at each size (`adb -s emulator-5554 shell wm size 2208x1768` open Fold, `1080x2340` phone; `wm size reset` after):
   `adb -s emulator-5554 shell uiautomator dump /sdcard/d.xml && adb -s emulator-5554 pull /sdcard/d.xml output/consistency-<date>/<layout>-<screen>.xml`
   Name files `fold-...` or `phone-...`; top-level pages `fold-top-pilastri.xml`, `fold-top-spese.xml`, ... (page-title x is compared only on `-top-` files).
4. `adb -s emulator-5554 shell wm density` gives the dpi; density = dpi / 160.
5. `node tools/consistency-check.mjs output/consistency-<date> --density <density> --out output/consistency-<date>/REPORT.md`
   Exit 1 if any deviation (+-1 dp) is not in `tools/consistency-exceptions.json` (`[{"rule":"...","screen":"...","text":"...","reason":"..."}]`, rule/screen/text are substring filters).

Rules: card-title top/left inset and height; card header (title centre below card top, trailing centre = title centre); card-bottom, card-left, card-right inset of the content; page-title/page-subtitle x, y, height; card left/right edges per pane; period-label prev/next vs the card below; section-label left vs the card below; chip height. The expected value is the most common value in the group.
Unit test `ConsistencyTagsTest` lists the card titles still drawn ad hoc (ignored until the fix owner builds one shared CardHeader).

## JVM layout tests (the gate on every build)

`app/src/test/java/xyz/grtlabs/pilastri/ui/layout/` renders every top-level screen (Pilastri, Spese, Futuro, Agente, Impostazioni) plus Mese, a pillar, Previdenza and Conti with the synthetic sample archive under Robolectric, at `w840dp-h673dp` (open Fold, `FoldLayoutConsistencyTest`) and `w411dp-h891dp` (cover, `PhoneLayoutConsistencyTest`), reads the tagged nodes' bounds and applies the rules of `consistency-check.mjs` and `critique-rules.md` ("Proposed checker rules (machine)"). One test per rule family; the rows (`screen | rule | element | measured | expected`) are in the failure message and in `app/build/layout-consistency/<fold|phone>.md`. Exceptions: `tools/consistency-exceptions.json`, same format.

`bash tools/gw.sh :app:testDebugUnitTest --tests "*LayoutConsistencyTest*" --tests "*SourceRulesTest*"` (counts in `app/build/test-results/testDebugUnitTest/*.xml`).

Measurement artefacts removed (R1, 2026-11-08; both engines): (1) a pane keeps the previous page composed underneath, so nodes that precede a LATER `page-content` of another title inside its pane/bounds are covered and dropped; (2) a card that ends at the bottom of the viewport is clipped and not measured for title/bottom-inset rows; (3) CR-55/CR-40 count per PANE (Fold: pane-left/pane-right) and REQUIRE an accent card only on Pilastri, Spese (both panes), Futuro, elsewhere at most one; (4) card insets use the outermost content child: `icon-disc` counts, a `chip` box replaces its inner text, full-width clickable rows only count left/right, desc-only full-width row nodes are containers; (5) neighbour period labels narrower than 16 dp (clipped pager peek) are not alignment-checked; a label is paired with the nearest card overlapping it horizontally, not by pane; (7) a `pill` node (PillButton box, Segmented cell) is the visible box for the card-inset lookup like a chip, but never joins the chip-height majority; (8) a clickable cut by the viewport bottom and shorter than 48 dp is not a touch row; (6) ConsistencyTagsTest accepts a tag applied through its `Modifier.xxxTag()` helper and ignores comments. The JVM run also writes `<layout>-nodes.txt` (id|text~desc|bounds, then the merged targets) for diagnosis.

Engine notes (G2, 2026-11-08): values the DESIGN.md "## Tokens" table fixes are asserted against the token, not the majority (card inset 14 on every side, 16 dp gutter, 8 dp gap, attention row 56); "same type, same measure" rules (card title, header centre, page-title y, labels, chip height) keep the majority. Card content = last texted/`chart` node inside the card (not its boxes, not the dock/island overlay); the right inset counts only content that spans the card. Touch = merged clickable nodes, deduped by bounds + label (JVM: the merged tree; checker: the dump's `clickable="true"`). Figure ratios (CR-56): JVM reads font sizes from the text layout; the checker compares line boxes (thresholds 1.3 / 2.0 for 26 / 17 / 11 sp). Colour rules have no fill semantics: `SourceRulesTest` scans the source for CR-57 (raw `fontSize`, Type sizes vs the Tokens table), CR-58, CR-59 outline, CR-60, CR-61, CR-62 radius. The harness verifies that Agente / Impostazioni really opened (`build/layout-consistency/<layout>-nav.txt`, and a `navigation:` row when a screen shows the same texts as Pilastri).

## Install

`bash tools/install-fold.sh` is the ONLY install path (`PHONE=host:port`, default `192.168.1.74:42975`; build with `tools/gw.sh :app:assembleFast` first). It refuses, with the reason and a non-zero exit, when: Pilastri is the top activity on the phone; the JVM layout tests (`LayoutConsistencyTest`, `ConsistencyTagsTest`, `LayoutTest`) fail; the newest `output/consistency-*/REPORT.md` is older than `app/build/outputs/apk/fast/app-fast.apk` or the checker re-run on its dumps has deviations outside the exceptions. Then it runs `adb install -r`, checks `lastUpdateTime` changed, and runs `cmd package compile -m speed -f`. It never uses run-as, uninstall or pm clear.

Checker reclassifications (D1, 2026-11-08, device dumps; the JVM engine already measured these correctly, no change there): (a) CR-33 reads visible `text` only; a node with empty `text` carries an accessibility description (chart summaries), which is read aloud, not drawn; (b) CR-24 centres the island in the safe area the panes occupy (`pane-right` top/bottom: status bar above, navigation bar below), not on the raw screen height; (c) the Setup flow (`*-setup-*`) is its own group for page-title/subtitle y (its back row and progress sit above the header); (d) CR-56 ratios skip a primary-figure cut by the scroll viewport (its box is not the line box); (e) a period label inside an accent card sits on the accent card's 16 dp side padding (`tok`), and its CO-MOTION partner is the stat strip under it, not the card below. Capture note: take a dump only after the page has settled; `fold-top-agente` of 2026-11-08b was caught mid-slide (page-title x 69 dp off, `pane-left` absent).

## Capture every screen (`tools/capture-all.sh`, 2026-11-09)

One command, emulator only (refuses any serial that is not `emulator-NNNN`), synthetic sample data only:

`bash tools/capture-all.sh [--config fold|cover|fs2|all] [--only 'phone-month*'] [--out <dir>] [-s emulator-5554] [--no-shots] [--no-motion] [--motion-all] [--list] [--crawl] [--legacy]`

- v2 (in-app capture): ONE intent per layout (`capture_all`, extras in `tools/capture-config.json`) makes the app walk every destination itself: navigate, settle (300 ms without a drawn frame), write its own semantics tree as uiautomator-format XML (`ui/CaptureDump.kt`: each node's attributes are read from the AccessibilityNodeInfo Compose's own accessibility provider builds, the tree walk follows the merged semantics tree, View wrappers and every other window are walked as views) plus a half-size PNG (PixelCopy), and `<n>-mid.*` for the previous month when the page has a `period-viewport`. Files go to `getExternalFilesDir/capture/<id>/`; the app logs `PILASTRI_CAPTURE done <id> ...`; the script runs ONE `adb pull`. Only the motion captures (real finger: hold, drag) still use `uiautomator dump`. `--legacy` runs the v1 per-screen uiautomator path (for equivalence checks).
- There is NO screen list in the tool. The app (`ui/CaptureHook.kt`) derives its destinations from the `Route` type's nested classes: objects as they are, classes with arguments expanded from the sample archive (accounts, installment plans, the latest 3 months, pillars 1-4; Category only `null`). A Route class with arguments the hook does not map is printed as FAIL and the run exits 1: add it to `CaptureHook.destinations`. `--list` prints what would be captured.
- (v1 description, kept for `--legacy`) Navigation is an intent (`am start --activity-single-top --es capture_route ...`), no taps, no restart. The app logs `PILASTRI_CAPTURE settled <id>` after 300 ms without a drawn frame; the script then takes ONE `uiautomator dump` and one screencap (half-size PNGs in `<out>/half/`). `wm size` and `font_scale` are set once per pass (fold 2208x1768, cover 1080x2340, fs2 = cover at font scale 2.0, no motion, first destination of each kind only); all are reset at the end.
- File names: `<fold|phone|phone-fs2>-<destination>` (`top-pilastri`, `top-agente`, `top-impostazioni`, `pillar-1`, `month-2026-11`, `pension`, `account-<id>`, ...). Every dump with a `period-viewport` also gets `<n>-vpK-rest/-moving` (finger down, held, dumped), `<n>-vpK-hold-{rest,short,long}` and the previous month's `<n>-mid.xml` + `<n>-mid-vpK-rest/-moving`, once per distinct viewport geometry per pass (`--motion-all`: every page). The checker needs no change: it reads the layout from the first name token, `-top-`, `-fs2`, `-rest/-moving` and `-hold-*`.
- Renames against the hand-written scripts: `fold-pillar` -> `fold-pillar-1..4`; `*-previdenza` -> `*-pension`; `*-mese` -> `*-month-<yyyy-MM>`; `*-impostazioni-conti` -> `*-connections` (pushed on its own, not over Impostazioni); strips: `fold-mese-rest` -> `fold-top-pilastri-vp1-rest`, `fold-spese-hold-*` -> `fold-top-spese-vp1-hold-*`; `fold-island-back` is not produced. The checker globs are unchanged; no fixture was renamed.
- Cost in v1 was the dump: `uiautomator dump` takes about 2.0 s on the emulator whatever the screen, so a run costs about 2.3 s per file plus the motion sleeps. `--only` and `--no-motion` are the levers.
